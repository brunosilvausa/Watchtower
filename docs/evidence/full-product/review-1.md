# Final review cycle 1 — reference/spec completeness

Date: 2026-10-22. Status: **CHANGES REQUIRED**. Independent read-only review of current source against the full-product spec/plan and supplied `admin-data.js`; only this report was written. No provider activation, remote calls, or test reruns. The controller's auth lazy-initialization fix was excluded as already in progress.

## Material findings

1. **P1 — Editing an API monitor silently replaces its protected workflow.** `apps/web/src/app/dashboard/monitor-form.tsx:43` supplies an example.com step when `config.steps` is absent, and line 25 sends it on every save. `packages/database/src/product-monitors.ts:6` intentionally removes encrypted steps from reads; lines 63–68 then replace them with the submitted example. Reproduction: create a multistep API monitor, reopen Edit, change only its name, save. The real workflow and its credentials are destroyed. Preserve protected steps unless the user explicitly replaces them; add a persisted edit regression.

2. **P1 — Converting an existing monitor to heartbeat produces an unusable monitor.** `packages/database/src/product-monitors.ts:67–73`: PATCH updates type/config but neither creates a heartbeat hash nor returns a token; only INSERT does. The type selector allows this transition. Reproduction: create HTTP, edit to heartbeat, save; no heartbeat URL is returned and its hash remains null. Generate a one-time token on transition (and retire an old heartbeat secret when leaving the type), or reject unsupported type changes explicitly.

3. **P2 — Public status settings are saved but ignored.** `apps/web/src/app/status/[slug]/status-view.tsx:15`: Wordmark always renders, and the component never reads `config.hideBranding` or `config.showResponseTime`. `packages/database/migrations/0004_product_access.sql:7` also omits response duration from the public component DTO. Reproduction: eligible Team workspace saves Hide branding and Show response time, publishes, opens page: branding remains and no response metric appears. Wire both settings through the real read/render path.

4. **P2 — Current open incidents disappear from the KPI when older than the chosen range.** `packages/database/src/product-dashboard.ts:6` filters all incident rows by `opened_at` before counting unresolved incidents. An outage opened two days ago remains ongoing but the 24h dashboard reports zero open incidents. Count current unresolved incidents independently; apply the selected range only to period metrics such as MTTR.

5. **P2 — Channel configuration cannot be repaired or re-enabled from the interface.** `apps/web/src/app/dashboard/product-views.tsx:50–52` exposes only Test and Remove for channels. Remove sets `enabled=false` in `product-resources.ts`, while rows remain listed and no edit/enable action exists. A channel created without credentials cannot later receive them without creating a duplicate; a removed channel cannot be restored. Add real edit/enable controls and prefill non-secret fields while preserving stored credentials on empty input.

6. **P2 — Platform feature management is unreachable on a fresh installation and lacks targeting.** `apps/web/src/app/dashboard/platform-view.tsx:12` only maps existing flags; schema creates an empty table and there is no creation control. The mutation function in `packages/database/migrations/0004_product_access.sql:10` writes enabled/rollout but never `workspace_ids`. The required targeting and rollout management is therefore incomplete even with full platform authorization. Add creation plus validated tenant targeting; no AI/browser implementation is requested.

7. **P2 — Required platform metrics are absent end to end.** `packages/database/migrations/0014_product_metrics_billing.sql:17` returns tenants/probes/flags only; `apps/web/src/app/dashboard/platform-view.tsx:8–12` renders only those lists. There is no MRR, churn or queue metric read/render path. Provider-derived subscription values exist, so this is implementation missingness rather than a live Stripe prerequisite. Return real metrics with unknown/unconfigured states where source evidence is absent, and show queue counts from persisted jobs.

8. **P2 — Dashboard omits the required expiry and observed-region reporting.** `packages/database/src/product-dashboard.ts:5–13` never selects `check_results.expires_at` or regional observation aggregates; `apps/web/src/app/dashboard/product-views.tsx:60–63` substitutes registered-probe capability listings for observation coverage. TLS/domain probes persist expiry, but users cannot see expiry dates/days remaining anywhere in the dashboard or detail table. Add persisted expiry and regional observation summaries; keep registration capabilities distinct from measured coverage. The existing observed-sample uptime ratio has no displayed observation coverage denominator, so long missing periods remain undisclosed alongside 100% uptime.

## Coverage disposition

Identity, workspace authorization, monitor CRUD, incidents, maintenance, invitation flows, billing adapters, API keys/webhooks, audit/preferences, public subscriptions and private-probe controls have concrete persisted service paths. This review does not certify all of them: cycles 2–5 must assess security, concurrency, browser behavior and regressions. The findings above prevent a complete-reference PASS. Additional interface limitations observed: no channel/maintenance edit control, no draft-status preview path, and no new-workspace creation control after the first workspace. These should be included in the controller's remaining completeness audit.

Local source review does not prove provider delivery, SSO/SCIM interoperability, passkey hardware behavior, deployed geographic coverage, hosted egress protection, load capacity or restore readiness. No tests were rerun in this review; fixes need targeted regressions and re-review before closing findings.
